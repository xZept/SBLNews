# Phase 0 Research: SBL News MVP

**Branch**: `001-sbl-news-mvp` | **Date**: 2026-11-26 | **Spec**: [spec.md](./spec.md)

## 1. Monorepo Workspace Separation & Deployment Topology

- **Decision**: Organize the repository as a two-workspace monorepo with `/web` (Next.js App Router, TypeScript strict, Tailwind CSS v4, shadcn/ui) and `/pipeline` (Python 3.12+, Pydantic v2, pytest), plus `/supabase/migrations` for sequential Git-first SQL schema and RLS migrations.
- **Rationale**:
  - Enforces Principle I (`$0/Month Free-Tier First`) by isolating the public/interactive Next.js application (deployed on Vercel Hobby) from the daily batch ingestion worker (executed on GitHub Actions scheduled cron).
  - Keeping SQL migrations in `/supabase/migrations` provides a single source of truth for schema, `pgvector` RPC functions, and RLS policies shared across `/web` and `/pipeline`.
- **Alternatives Considered**:
  - *Single full-stack Next.js app with Vercel Cron ingestion*: Rejected because Vercel Hobby cron limits (1/day with strict serverless execution timeouts) cannot reliably handle multi-source PubMed/OpenAlex fetching, full-text PMC inspection, rate-limit backoff, and batch Gemini structured extraction.
  - *Always-on Python FastAPI ingestion server on Render/Railway*: Rejected because always-on compute violates the $0/month hobby constraint and Render Free spins down after inactivity.

## 2. Tailwind CSS v4 Namespace Reset & Primitive-Level shadcn/ui Overrides

- **Decision**: In `/web/src/app/globals.css`, use Tailwind CSS v4 `@import "tailwindcss";` with an explicit `@theme` block that resets default color namespaces (`--color-*: initial;`) and defines only the normative Neo-Brutalist Sky Blue tokens (`#F8FAFC` canvas, `#FFFFFF` card surface, `#0F172A` ink/border, `#38BDF8` sky-blue accent, `#475569` muted text, and semantic evidence/transparency pastel tokens). Override shadcn/ui primitives (`Card`, `Badge`, `Button`, `Input`, `Tabs`) directly in `/web/src/components/ui/*` with `2px solid #0F172A` borders, hard zero-blur offset shadows (`4px 4px 0px #0F172A` for cards, `2px 2px 0px #0F172A` for controls with `active:translate-x-[2px] active:translate-y-[2px] active:shadow-none`), and max corner radii (`rounded-md` / `6px` for cards, `rounded-sm` / `4px` for badges).
- **Rationale**:
  - Satisfies Principle III (`Neo-Brutalist Sky Blue Design System`) by making purple/violet/indigo utilities, soft rings, and blurred shadows impossible to use accidentally via default Tailwind classes.
  - Primitive-level overrides ensure every screen across the 6 MVP routes inherits consistent Neo-Brutalist geometry without repeating ad-hoc class overrides.
- **Alternatives Considered**:
  - *Keeping default Tailwind v4 colors and relying on code review*: Rejected because constitution Principle III explicitly mandates clearing `--color-*: initial;` inside `@theme`.
  - *Wrapping shadcn/ui components in secondary custom components*: Rejected because direct primitive overrides eliminate the risk of importing unstyled default primitives.

## 3. Next.js App Router Caching (ISR) vs. Dynamic Authenticated Mutations

- **Decision**:
  - Render `/` (Main Research Feed) and `/guidelines` (Living Evidence Matrix) using Incremental Static Regeneration (`revalidate = 3600` plus on-demand `revalidatePath` triggered after admin review approvals or webhook/revalidation calls) so public reads serve instantaneously from cache.
  - Handle user-specific upvote state and mutations via authenticated client/server actions backed by `@supabase/ssr` cookie sessions and Zod input validation.
  - Render `/methodology` statically at build time (`force-static`).
  - Render `/study/[id]` with cached study details + dynamic or revalidated discussion threads, `/search` dynamically via server-side hybrid search RPC, and `/admin/review` dynamically with strict server-side `role === 'admin'` verification before any query or mutation executes.
- **Rationale**:
  - Directly satisfies Principle I and FR-003 (ISR for `/` and `/guidelines`) and Principle IV (server-side RBAC on `/admin/review`).
- **Alternatives Considered**:
  - *Force-dynamic rendering on `/` and `/guidelines`*: Rejected because it violates Principle I and FR-003 by coupling public page loads to live database latency on every visit.

## 4. Supabase PostgreSQL + `pgvector` Hybrid Search & Egress Protection

- **Decision**:
  - Enable the PostgreSQL `vector` extension (`pgvector`) and store 768-dimension normalized embeddings (`vector(768)`) generated by the Gemini embedding API (`text-embedding-004` / Gemini embeddings) alongside a generated `tsvector` full-text search column (`search_tsv`) on `studies`.
  - Implement hybrid search via a PostgreSQL RPC function `search_studies_hybrid(...)` using Reciprocal Rank Fusion (RRF) combining full-text rank (`ts_rank_cd`) and cosine similarity (`1 - (embedding <=> query_embedding)`), filtered deterministically by `study_design`, `min_duration_weeks`, and `is_trained_population`.
  - Strictly project summary columns only (`id`, `doi`, `pubmed_id`, `title`, `journal`, `publication_year`, ` published_at`, `study_design`, `population`, `is_trained_population`, `sample_size_n`, `duration_weeks`, `primary_outcome`, `summary_takeaway`, `inspection_depth`, `quality_score`, `upvote_count`, `comment_count`) and never return `abstract_text`, `full_text_content`, or `embedding` in feed/list/search queries.
- **Rationale**:
  - Satisfies Principle IV (`Performance, Egress & Security Guardrails`) and FR-007/FR-013 by keeping list payloads under ~2 KB per study card (protecting Supabase Free's 5 GB/month egress budget) while delivering both exact keyword and semantic discovery in a single database round-trip.
- **Alternatives Considered**:
  - *Client-side or application-layer vector re-ranking (`SELECT *` into Next.js)*: Rejected because transferring `vector(768)` and full abstracts across the wire would rapidly exhaust Supabase Free egress limits and violates Principle IV.
  - *External vector database (Pinecone/Qdrant)*: Rejected by Principle I stack discipline.

## 5. Primary Literature Ingestion & Inspection Depth Detection (`/pipeline`)

- **Decision**:
  - Build modular fetchers in `/pipeline/src/fetchers/` for:
    1. **PubMed E-utilities (`esearch` + `efetch`)** and **PubMed Central (PMC) Open Access full-text XML** (when a PMCID is linked and full text is available).
    2. **OpenAlex API (`works` endpoint)** filtered by resistance-training / exercise-science concepts and open-access full-text locations.
    3. **Targeted Exercise-Science Journal RSS feeds** (*Journal of Strength and Conditioning Research*, *Sports Medicine*, *British Journal of Sports Medicine*, *Journal of Applied Physiology*, *European Journal of Sport Science*, *Medicine & Science in Sports & Exercise*).
  - Normalize records and deduplicate by canonical identifiers (`doi`, `pubmed_id`, `openalex_id`) prior to LLM invocation so no duplicate extraction calls or duplicate rows occur.
  - Set `inspection_depth = 'Full-Text'` strictly when complete article body text (e.g., via PMC Open Access XML or open-access full text) is retrieved and passed to extraction; otherwise set `inspection_depth = 'Abstract-Only'`.
- **Rationale**:
  - Satisfies Principle II (`Primary Sources First` and `Inspection Transparency Badges`) and conserves Gemini API free-tier quota by deduplicating before extraction.
- **Alternatives Considered**:
  - *Scraping paywalled publisher HTML*: Rejected for legal/reliability reasons and fragility; abstract-only records are transparently badged `Abstract-Only`.

## 6. Gemini 3.5 Flash Lite Structured Extraction vs. Deterministic Evidence Scoring

- **Decision**:
  - Invoke `gemini-3.5-flash-lite` via the official `google-genai` Python SDK using `response_mime_type="application/json"` and `response_schema=StudyExtractionSchema` (Pydantic v2 model).
  - Restrict the LLM schema strictly to factual extraction fields:
    - `study_design`: enum (`meta_analysis`, `systematic_review`, `rct`, `controlled_trial`, `cohort_observational`, `acute_crossover`, `animal_in_vitro`, `review_commentary`)
    - `population`: concise description + boolean flags `is_human`, `is_trained_population`, `is_acute_emg_only`
    - `sample_size_n`: `int | None` (never fabricated if unreported in abstract)
    - `duration_weeks`: `float | None` (never fabricated if unreported)
    - `primary_outcome`: concise string
    - `summary_takeaway`: strictly 2-sentence actionable scientific summary
    - `limitations`: list of methodological caveats
    - `matched_guideline_ slugs`: list of matching active guideline variable slugs (`weekly-volume`, `rir-failure`, `frequency`, `rest-intervals`, `lengthened-partials`, `protein-intake`)
  - Compute `quality_score` (0-100 integer) and `publication_status` (`published`, `pending`, `rejected`) **100% deterministically in Python (`scoring.py`)**:
    - Human Meta-Analysis / Systematic Review: Base `85`
    - Human RCT (`duration_weeks >= 8`): Base `75`
    - Human Controlled Trial (`duration_weeks >= 8`): Base `65`
    - Human RCT / Controlled Trial (`duration_weeks < 8` or unspecified): Base `55`
    - Observational / Cohort: Base `40`
    - Modifiers:
      - `is_trained_population == True`: `+15`
      - `sample_size_n >= 30` (trials) or `>= 10` studies/200 subjects (meta-analyses): `+5`
      - `inspection_depth == 'Full-Text'`: `+5`
      - `is_acute_emg_only == True`: `-45` (downranked below public auto-publish threshold)
      - `is_human == False` or `study_design == 'animal_in_vitro'`: score capped at `10` and `publication_status = 'rejected'` (excluded from public feed)
    - Auto-publish threshold: Human studies with `quality_score >= 60` and complete required takeaways publish automatically (`published`), borderline studies (`35 <= quality_score < 60`) enter `pending` for `/admin/review`, and animal/acute-EMG-only noise (`< 35`) is downranked/filtered.
  - Whenever an ingested study has `study_design in ('meta_analysis', 'systematic_review')` and matches one or more `matched_guideline_slugs`, `/pipeline` inserts a `consensus_drift_alerts` record (`status = 'pending'`) for `/admin/review` without mutating `guidelines`.
- **Rationale**:
  - Enforces Principle II (`Extraction vs. Scoring Separation` and `HITL Living Guidelines`) and satisfies SC-003 (100% deterministic test verification).
- **Alternatives Considered**:
  - *Asking Gemini to output a `1-100` quality score*: Explicitly prohibited by Principle II.
